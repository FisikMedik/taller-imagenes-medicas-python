De radiografías a predicciones

Un primer modelo de aprendizaje automático

Juan Calderón · Módulo opcional del taller de imágenes médicas · ML Honduras 2026

Estas imágenes tienen una etiqueta de referencia. ¿Puede un programa aprender de unos ejemplos y clasificar otros que no utilizó para ajustar sus pesos?

Radiografías pediátricas de PneumoniaMNIST, reducidas por sus autores a 28 × 28 píxeles. Los rótulos son etiquetas del conjunto; no son una interpretación médica hecha en este taller.

Qué vamos a construir

Entrenaremos un clasificador supervisado: recibe una imagen y aprende a relacionar sus números con una etiqueta, 0 = normal o 1 = neumonía, según el conjunto. Usaremos regresión logística, un modelo sencillo que permite explicar los pasos y funciona con CPU. Aunque se llama «regresión», aquí realiza clasificación. No es una red neuronal convolucional.

Duración: 45–60 minutos adicionales. Es una ampliación opcional; no sustituye la sesión original de una hora ni anuncia un cambio del programa de la escuela. Para una demostración de 15 minutos, lee las salidas guardadas de las celdas 1, 6, 9 y 11; reserva la práctica completa para otra sesión.

Antes de comenzar: abre este cuaderno en Colab, usa CPU y ejecuta cada celda en orden con su triángulo o Mayús + Enter. No necesitas montar Drive ni subir estudios propios. La preparación de bibliotecas y la primera descarga necesitan internet. El repositorio completo incluye una copia del archivo público para usarla localmente tras instalar las bibliotecas. Las imágenes y resultados ya están guardados para poder leerlos sin ejecutar.

Un acuerdo antes de mirar resultados

Usaremos entrenamiento para aprender los pesos, validación para elegir entre tres valores de C y prueba para el informe final. El umbral final será 0.5, fijado de antemano. Experimentaremos con otros umbrales solo en validación. No cambiaremos el modelo después de consultar prueba para mejorar el número publicado.

Alcance: ejercicio educativo con imágenes pequeñas y etiquetas de un repositorio. «Normal» no garantiza ausencia de cualquier enfermedad. La puntuación del modelo no es un riesgo clínico validado. Un buen resultado aquí no demuestra que funcione en pacientes nuevos, otro hospital, otras edades o imágenes originales.

Cómo funciona esta celda

  • import carga herramientas; np y plt son nombres breves para NumPy y Matplotlib. Una biblioteca es un conjunto de funciones reutilizables.
  • find_spec comprueba si una biblioteca existe. Solo se instalan las ausentes; se conservan y registran las versiones del entorno. Si falla una instalación, se detiene el ejercicio con un mensaje. Los intervalos de requisitos no congelan un entorno idéntico.
  • ¿Por qué mi salida puede diferir del PDF? Las figuras guardadas corresponden a NumPy 2.5.4, Matplotlib 3.11.2 y scikit-learn 1.9.1. Otra ejecución completa en Colab, con scikit-learn 1.6.1, seleccionó C=1 frente a C=0.1 de la referencia. Los resultados de validación de ambos candidatos son próximos; distintas versiones pueden cambiar la elección. Guarda tus versiones y resultados; no cambies los ajustes mirando prueba para hacerlos coincidir con el manual.
  • Path representa la ubicación del archivo. La copia local tiene prioridad; urlopen descarga datos públicos si falta. No descarga ni ejecuta código ajeno.
  • sha256(...).hexdigest() calcula una huella del contenido. assert detiene la celda si no coincide con la copia auditada. No se continúa silenciosamente con otro archivo.
  • .npz reúne arreglos de NumPy. allow_pickle=False evita cargar objetos serializados. Los nombres train, val y test indican las particiones oficiales; images guarda imágenes y labels, etiquetas.
  • Una forma (4708, 28, 28) significa 4.708 imágenes con 28 filas y 28 columnas. uint8 guarda enteros sin signo entre 0 y 255. .ravel() convierte las etiquetas de una columna a un vector.
  • flatnonzero(condición) devuelve posiciones que cumplen una condición; [:3] toma las tres primeras. La galería no se eligió por lo bien que funcione el modelo.
  • subplots(2,3) crea seis paneles. El bucle for empareja cada panel con una imagen. imshow dibuja valores como grises; vmin y vmax fijan una escala común; nearest muestra los píxeles sin inventar suavizado. plt.show() presenta la figura antes del informe técnico.

Observa, prueba y comprueba

Celda 02 · Tres grupos y una revisión de duplicados

Antes de aprender, separaremos las funciones de los datos. Entrenamiento permite ajustar los pesos; validación ayuda a elegir ajustes; prueba se reserva para el informe final. Nunca mezclamos ni redistribuimos sus miembros.

La auditoría detectó 18 copias exactas adicionales dentro de entrenamiento y 8 imágenes de validación idénticas a imágenes de entrenamiento. Conservamos la primera ocurrencia de cada imagen en entrenamiento y excluimos esas 8 de validación. Así trabajaremos con 4.690 / 516 / 624 imágenes. Prueba mantiene sus 624 imágenes oficiales, incluidas 3 copias exactas adicionales internas. Son conteos de imágenes, no de pacientes independientes.

Cómo funciona esta celda

  • np.unique(..., axis=0) compara imágenes completas, no píxeles sueltos. return_index=True devuelve la primera aparición de cada matriz; sort conserva su orden original.
  • imagenes_train[ids] selecciona imágenes; los mismos índices seleccionan sus etiquetas. Imagen y etiqueta deben seguir emparejadas.
  • tobytes() representa los píxeles exactamente. El conjunto {...} permite comprobar si una matriz de validación ya aparece en entrenamiento. Esto detecta igualdad exacta, no imágenes casi iguales ni identidad de personas.
  • conservar_val es una máscara de verdaderos y falsos; se aplica a imágenes y etiquetas. ~ invierte esa máscara. ids_val conserva el índice original para que los ejemplos se puedan localizar.
  • bincount cuenta etiquetas 0 y 1. bar dibuja los conteos y bar_label escribe sus números. El segundo panel resume el uso previsto de cada partición.
  • El archivo descargado permanece intacto: las exclusiones ocurren en memoria. Es una variante docente documentada del conjunto; sus resultados no se presentan como comparación idéntica al protocolo oficial.

Privacidad e independencia: el NPZ contiene arreglos de imágenes y etiquetas, sin campos DICOM o identificadores de pacientes con los que podamos auditar su separación. No encontrar matrices idénticas entre entrenamiento y prueba no demuestra independencia por paciente. Reducir una imagen, convertirla a NPZ o publicarla en internet tampoco constituye por sí solo anonimización. Para datos propios se requiere una revisión específica de metadatos, texto incrustado y permisos antes de compartirlos.

Observa, prueba y comprueba

Pregunta: si la misma imagen aparece en entrenamiento y validación, ¿es una comprobación completamente nueva? Respuesta: no; hay fuga de datos, porque el modelo ya tuvo acceso a ese ejemplo. Aquí retiramos las coincidencias exactas antes de elegir ajustes.

Pregunta: ¿quitar duplicados demuestra que son pacientes distintos? Respuesta: no. Una persona puede tener radiografías diferentes. Harían falta identificadores adecuados y un protocolo de separación por paciente, además de controles de similitud.

Celda 03 · De una imagen a 784 características

Una muestra será una imagen. Una característica será el valor de uno de sus píxeles. X reúne características y y contiene la etiqueta de referencia. Convertimos cada imagen en una fila y dividimos por 255 para expresar sus valores entre 0 y 1. Esta operación fija no aprende estadísticas de validación ni prueba.

Cómo funciona esta celda

  • reshape(N, -1) organiza N imágenes como N filas y calcula automáticamente las 784 columnas. Sigue el orden de filas de cada imagen; no baraja píxeles ni etiquetas.
  • astype(np.float64) permite números decimales. Dividir por 255 transforma 0 en 0 y 255 en 1. No ajustamos el contraste por separado para cada imagen.
  • X_train se usará en fit; X_val se usará para evaluar opciones. Aún no preparamos X_test para inferencia.
  • El perfil central recorre los 784 valores. Los saltos de una fila de la imagen a otra también aparecen en ese orden; no es un perfil anatómico continuo.
  • Aplanar no elimina los valores ni su orden: cada columna sigue correspondiendo a una posición. Sin embargo, la regresión logística no utiliza una operación de vecindad como la convolución de una CNN.
  • La etiqueta y es la respuesta que intentamos aprender a predecir; no se añade como columna de X, porque eso revelaría directamente la respuesta.

Observa, prueba y comprueba

Celda 04 · Qué aprende la regresión logística

El modelo aprende un peso por característica y un término independiente. Para cada imagen suma «peso × valor» en sus 784 posiciones y añade ese término. El resultado, z, pasa por una función llamada sigmoide, que lo lleva al intervalo 0–1. Con umbral 0.5 asignaremos etiqueta 1 cuando la puntuación sea al menos 0.5.

La figura siguiente explica esa función con números artificiales; todavía no es el resultado de entrenar con radiografías. z puede ser negativo, cero o positivo.

Mostrar el código de la celda 4
z = np.linspace(-6, 6, 400)
p = 1 / (1 + np.exp(-z))
fig, ax = plt.subplots(figsize=(9, 4.4), layout="constrained")
ax.plot(z, p, color="#007f89", linewidth=3)
ax.axhline(0.5, color="#c96932", linestyle="--", label="Umbral ilustrativo: 0.5")
ax.axvline(0, color="#697887", linestyle=":")
for valor in [-2, 0, 2]:
    salida = 1 / (1 + np.exp(-valor))
    ax.scatter(valor, salida, color="#102c40", zorder=3)
    ax.annotate(f"z={valor} → {salida:.2f}", (valor, salida), xytext=(8, 12), textcoords="offset points")
ax.set(title="De suma ponderada a puntuación: la sigmoide", xlabel="z = suma de pesos × píxeles + término independiente", ylabel="Puntuación entre 0 y 1", ylim=(-0.03, 1.10))
ax.legend(loc="lower right")
plt.show()
print("Estos puntos ilustran la función. Los pesos reales se aprenderán en la celda 6.")

Cómo funciona esta celda

  • linspace(-6,6,400) crea 400 valores uniformemente espaciados para dibujar una curva suave.
  • exp calcula la exponencial. La expresión 1/(1+exp(-z)) es la sigmoide: valores grandes positivos se acercan a 1 y negativos a 0.
  • axhline marca el umbral horizontal y axvline, la suma cero. Con z=0, la salida es exactamente 0.5. scatter marca ejemplos y annotate escribe sus resultados.
  • Aprender consiste en ajustar pesos para reducir los errores de las puntuaciones frente a etiquetas conocidas, con una penalización que evita pesos excesivos. No escribimos una regla clínica que busque una lesión.
  • Después de entrenar, predict_proba devuelve probabilidades estimadas por ese modelo. En el tutorial las llamamos puntuaciones para recordar que no se ha validado su calibración clínica: una salida 0.8 no permite afirmar «este paciente tiene un 80 % de riesgo».

Observa, prueba y comprueba

Pregunta: si z = -2, ¿el modelo decidiría etiqueta 1 con umbral 0.5? Respuesta: no; la sigmoide es aproximadamente 0.119, menor que 0.5.

Pregunta: ¿esta curva es una medición en radiografías? Respuesta: no; es una explicación matemática de cómo se transforma la suma. Las predicciones reales aparecerán después del entrenamiento.

Celda 05 · Una referencia que ignora las imágenes

Antes del modelo, probamos una regla trivial: predecir siempre la clase más frecuente de entrenamiento. Un modelo útil debería aportar algo frente a esa referencia. La abundancia de una clase puede producir una exactitud aparentemente alta aunque la otra nunca se reconozca.

Mostrar el código de la celda 5
referencia = DummyClassifier(strategy="most_frequent")
referencia.fit(X_train, y_train)
pred_base_val = referencia.predict(X_val)
base_val = [accuracy_score(y_val, pred_base_val), balanced_accuracy_score(y_val, pred_base_val)]
fig, ax = plt.subplots(figsize=(8.5, 4), layout="constrained")
barras = ax.bar(["Exactitud", "Exactitud equilibrada"], np.array(base_val)*100, color=["#697887", "#c96932"])
ax.bar_label(barras, labels=[f"{v:.1%}" for v in base_val], padding=4)
ax.set(title="Validación · siempre predecir la clase mayoritaria", ylabel="Porcentaje", ylim=(0, 105))
plt.show()
print("Predicción constante:", nombres[int(pred_base_val[0])])
print("Exactitud = aciertos / todas las imágenes.")
print("Exactitud equilibrada = (sensibilidad + especificidad) / 2.")

Salida guardada · celda 5

Predicción constante: Neumonía (etiqueta 1)
Exactitud = aciertos / todas las imágenes.
Exactitud equilibrada = (sensibilidad + especificidad) / 2.

Cómo funciona esta celda

  • DummyClassifier es una referencia sencilla, no nuestro modelo de imágenes. most_frequent usa la etiqueta más abundante en y_train.
  • fit(X_train,y_train) permite aprender esa frecuencia del grupo de entrenamiento. predict(X_val) genera una respuesta para cada muestra de validación; esta regla ignora sus píxeles.
  • accuracy_score divide aciertos entre imágenes totales. balanced_accuracy_score promedia el reconocimiento de las dos clases, dando el mismo peso a cada una.
  • En clasificación binaria, sensibilidad será la fracción de etiquetas 1 recuperadas como 1; especificidad, la fracción de etiquetas 0 recuperadas como 0. Usaremos esos nombres respecto a las etiquetas del conjunto, no como validación clínica.
  • Una regla que siempre predice 1 tiene sensibilidad 100 % y especificidad 0 % cuando ambas clases están presentes. Su exactitud equilibrada es 50 %, aunque su exactitud global sea mayor.

Observa, prueba y comprueba

Pregunta: ¿una exactitud cercana al 74 % demuestra que aprendió a leer radiografías? Respuesta: no. En esta validación, 381 de 516 imágenes tienen etiqueta 1. Predecir siempre 1 acierta 381/516 ≈ 73.84 % sin mirar ninguna imagen. La exactitud equilibrada revela que una clase nunca se recupera.

Celda 06 · Entrenar y elegir usando validación

Entrenaremos tres opciones de regularización. C controla la intensidad de la penalización: menor C significa mayor penalización de los pesos. No significa número de capas ni número de imágenes. Elegiremos la mayor exactitud equilibrada de validación; si empatan, conservaremos el menor C porque las opciones están ordenadas.

class_weight="balanced" aumenta el peso relativo de los ejemplos de la clase menos frecuente durante el ajuste. No inventa imágenes ni equilibra físicamente los grupos.

Mostrar el código de la celda 6
opciones_C = [0.01, 0.1, 1.0]
modelos, resultados_C = [], []
for C in opciones_C:
    candidato = LogisticRegression(C=C, solver="lbfgs", max_iter=2000, class_weight="balanced", tol=1e-4)
    candidato.fit(X_train, y_train)
    assert candidato.n_iter_[0] < 2000, "El ajuste llegó al límite; revisa la convergencia antes de comparar."
    score_train = balanced_accuracy_score(y_train, candidato.predict(X_train))
    score_val = balanced_accuracy_score(y_val, candidato.predict(X_val))
    modelos.append(candidato)
    resultados_C.append([C, score_train, score_val])
resultados_C = np.array(resultados_C)
mejor = int(np.argmax(resultados_C[:, 2]))
modelo = modelos[mejor]
C_elegido = float(resultados_C[mejor, 0])
fig, ax = plt.subplots(figsize=(9, 4.2), layout="constrained")
ax.plot(opciones_C, resultados_C[:, 1]*100, "o-", color="#697887", label="Entrenamiento")
ax.plot(opciones_C, resultados_C[:, 2]*100, "s-", color="#007f89", label="Validación")
ax.scatter(C_elegido, resultados_C[mejor, 2]*100, s=170, facecolors="none", edgecolors="#c96932", linewidths=2, label="Opción elegida")
ax.set(xscale="log", title="Elegir C sin consultar prueba", xlabel="C · menor valor = mayor regularización", ylabel="Exactitud equilibrada (%)", ylim=(50, 100))
ax.legend()
plt.show()
for C, tr, va in resultados_C:
    print(f"C={C:g} · entrenamiento {tr:.2%} · validación {va:.2%}")
print(f"Elegido por validación: C={C_elegido:g}; prueba aún no se utiliza para predecir.")

C=0.01 · entrenamiento 93.52% · validación 92.99%
C=0.1 · entrenamiento 95.37% · validación 95.05%
C=1 · entrenamiento 97.15% · validación 94.91%
Elegido por validación: C=0.1; prueba aún no se utiliza para predecir.

Cómo funciona esta celda

  • LogisticRegression(...) configura una opción. lbfgs es el método numérico que ajusta los pesos. max_iter limita pasos del ajuste; no es el número de ejemplos. tol establece una tolerancia numérica para detenerlo.
  • fit recibe exclusivamente entrenamiento. Los pesos ajustados quedan en el objeto candidato. No llamamos fit con validación ni prueba.
  • predict aplica el modelo ya ajustado. Comparamos entrenamiento y validación para observar si los resultados aprendidos se mantienen en ejemplos no utilizados para ajustar pesos.
  • append conserva cada modelo y sus resultados. argmax busca la posición con mayor valor en la tercera columna, la puntuación de validación; en empate devuelve la primera.
  • modelo referencia el candidato elegido, sin volver a entrenarlo. No se reajusta con entrenamiento más validación: así el procedimiento permanece sencillo y verificable.
  • El eje horizontal es logarítmico: cada paso multiplica C por 10. No hay una garantía de que un C mayor mejore validación. Una diferencia de pocos ejemplos también puede cambiar el ganador.
  • Elegir repetidamente ajustes sobre la misma validación puede sobreajustarla. Esta práctica limita de antemano la búsqueda a tres opciones. Estas comparaciones no convierten validación en una evaluación externa.

Observa, prueba y comprueba

Celda 08 · Cambiar un umbral cambia los errores

Sin reentrenar, probaremos umbrales 0.3, 0.5 y 0.7 solo en validación. Bajar el umbral facilita decidir etiqueta 1; puede recuperar más referencias 1 y también equivocarse más con referencias 0. No existe un umbral universalmente mejor al margen del propósito y de los costes de los errores.

Esta exploración no selecciona un nuevo umbral para el informe: conservamos 0.5, fijado antes de mirar resultados.

Cómo funciona esta celda

  • json.dumps(..., indent=2) organiza ese texto; ensure_ascii=False conserva tildes legibles. write_text lo guarda en la carpeta actual, sobrescribiendo únicamente el informe de este módulo si se reejecuta.
  • En Colab, abre el icono de carpeta de la barra lateral, localiza resultados_modulo_ml.json, abre su menú y elige descargar. El archivo no se guarda automáticamente en tu Drive; la sesión de Colab es temporal.
  • La ficha conserva resultados medidos, no cifras inventadas. Versiones o tolerancias numéricas diferentes pueden producir pequeñas variaciones: registra siempre la ejecución real.
  • Para repetir la ruta docente, reinicia el entorno, conserva los parámetros de referencia y ejecuta en orden. Para comparar cifras, compara también versiones, datos y ajustes: el mismo recorrido no garantiza números idénticos entre entornos distintos. Repetir el cálculo no convierte prueba en nuevos pacientes.

Observa, prueba y comprueba

Cierre con respuestas completas

  1. ¿Qué aprendió? Pesos que relacionan 784 valores de píxeles con dos etiquetas en estas imágenes; no una regla clínica universal.
  2. ¿Qué impide evaluar solo con entrenamiento? Ya se utilizó para ajustar esos pesos, por lo que puede dar una visión demasiado favorable.
  3. ¿Por qué validación y prueba son distintas? Validación participó en la elección de C; prueba se reservó hasta fijar decisiones.
  4. ¿Qué falta para un uso clínico? Entre otras cosas, población y finalidad definidas, referencia adecuada, auditoría por paciente, evaluación externa, análisis de sesgos, calibración cuando sea necesaria y validación/regulación correspondientes. Este taller no realiza ese proceso.
  5. ¿Y una CNN? Una red convolucional aprende filtros y jerarquías espaciales; sería una ampliación posterior. Los principios de separación, referencias y evaluación siguen siendo necesarios.
